# SDD / TDD 铁律（Engineering Process）

> 本文件是**强制工程流程**。违反任何一条 = 返工。
> 业务执行协议（翻译流水线怎么跑）见 `AGENTS.md`；本文件管「代码怎么改」。

## 何时走 SDD（规格先行）

任何满足以下之一的改动，**必须先写/改文档、经用户确认后再动代码**：

- 新增/修改阶段、子命令、闸门、退出码、产物文件格式（控制面：ADR-030）
- 新增守卫、自动拦截、置信度阈值等质量防线（参照 ADR-031）
- 修改声学时间戳语义、状态链、decisions 落盘语义
- 依赖变更、模块边界调整、数据格式变更

SDD 产物：`docs/adr/NNN-*.md`（架构决策，编号递增不复用；含背景证据/决策/测试计划/后果）
或 `docs/specs/NN-*.md`（行为规格）。**纯笔误修复不需要 SDD。**

## TDD 铁律（红-绿-重构）

1. **先写失败测试**：新函数 → 测试先行（ImportError 也算红）；修 bug → 必须先有
   复现该 bug 的失败测试。**禁止先实现后补测试。**
2. 红灯必须落在正确位置（断言失败于被测行为，不是收集错误）。
3. 最小实现到绿；禁止为过测试改测试语义（改测试 = 需要说明理由）。
4. **全量回归**：`uv run pytest -q` 全绿才许提交（当前基线 442 passed, 12 skipped）。
   只跑单个文件不算验收。
5. 测试通过后同步文档（AGENTS.md 红线表 / Spec / ADR），最后提交。
   代码+测试+文档+验证命令 = 完成定义（DoD）四件套。

## 事故驱动的固化义务

每个线上事故（幻觉漏网、闸门误伤、状态丢失）必须沉淀为：
回归测试（用**真实事故几何数据**命名，如 39.26-40.16s）+ ADR + AGENTS.md 红线表登记。
例：kathy_meta_vlog 幻觉 → ADR-031；sha 闸门误伤 → `test_resegment_refreshes_segments_sha_anchor`。

## E2E 验证

影响转写/生成/校验链路的改动，提交前用 **`%TEMP%` 副本**做实弹冒烟
（真实模型跑一次关键路径），**绝不触碰 `videos/` 真实产物**；冒烟后删除临时目录。
